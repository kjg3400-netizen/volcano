## ★조용히 틀리는 곳 — 여섯

### 1. 인코딩이 셋이다

5ch `subject.txt` = **cp932(Shift-JIS)** · 痛いニュース = **euc-jp** · 나머지 utf-8.
utf-8 로 못박으면 **오류 없이 제목만 깨진다.** `get_text()` 가 헤더→메타→cp932→euc-jp 로 내려간다.

### 2. 5ch 는 HTML 이 아니다 — `norm_ws()` 를 걸면 안 된다

```
1787237849.dat<>【速報】…… ★2 [ぐれ★] (597)
```
한 줄이 한 스레다. 공백을 뭉개면 줄이 하나로 붙어 통째로 못 읽는다.
**HTML 소스에는 반드시 `norm_ws()` 를 걸고, 5ch 에는 걸지 않는다.**

### 3. `★2` 를 안 세면 제일 터진 스레가 밀린다

`★2`·`★5` 는 **続きスレ** 다. 앞 스레가 1000레스를 채워 넘어온 것이니
실제 반응은 `(순번-1)×1000 + レス수` 다. 이걸 빼먹으면 5,000레스짜리가
`(120)` 으로 보여 목록 아래로 사라진다.

### 4. ヤフコメ 랭킹에 `newsFeed_item` 은 없다

이 페이지에 있는 건 `newsFeed_item_body` 뿐이고, 그건 **기사 링크보다 뒤에** 온다.
행 경계로 쓰면 **0건**이 나온다. 목록은 `<ol class="newsFeed_list">` 안의
`<li data-ual-view-type="list">` 다. 클래스가 전부 해시(`sc-1hy2mez-8`)라
**모양으로 가른다** — 제목은 텍스트 조각 중 가장 긴 것.

### 5. Togetter 행 클래스가 두 가지다

`<li class=" clearfix">` 와 `<li class=" has_thumb clearfix">`.
앞의 것만 잡으면 **25건 중 10건**만 온다.

### 6. 검색결과 제목이 `<em>` 으로 쪼개진다

Yahoo 검색은 검색어를 `<em>` 으로 감싼다. 그대로 텍스트를 뽑으면
`東武鉄道` `４人` `死亡事故` 로 흩어져 **겹침이 전부 0.00** 이 된다.
게다가 한 기사에 앵커가 둘(썸네일+제목)이라 `_cl_link:title` 로 자르면
**건수가 두 배(39·40건)로 부푼다.**
→ `<em>` 을 먼저 지우고, **기사 id 로 묶어** 그 id 의 가장 긴 텍스트를 제목으로 본다.

## ★★확산은 '사이트 수'가 아니라 '계열 수'로 센다

이번에 제일 크게 고친 곳이다.

5ch 세 판(ニュース速報+·芸スポ+·嫌儲)과 마토메 두 곳은 **서로 다른 커뮤가 아니다.**
마토메는 5ch 를 베껴 오고, 세 판은 같은 사람들이 판만 옮겨 세운다.
그대로 세면 5ch 화제 하나가 **'5개 커뮤 동시 확산'** 으로 둔갑해
小町·ガルちゃん 의 진짜 원본 논쟁을 전부 눌러 버린다.

```
SITE_FAMILY = 5ch(3판+마토메2) · garu(2) · komachi(2) · hatena(3) · togetter(2) · yahoo(3)
spread = 48·log10(계열수) + 10·log10(글수)
```

## 짧은 제목이 긴 제목에 흡수된다 — 겹침 하한을 올린다

일본어는 조사·활용이 한 글자라 글자쌍이 우연히 겹치기 쉽다.
분모가 `min(len)` 이라 **짧은 제목이 아무 긴 제목에나 붙는다.**

```
「こんなテレビ番組が見たい(要望)」  →  「こんなところになぜ食パン…投棄」 에 붙음
「三山凌輝はなぜモテるのか？」      →  「なぜSAPIX→…東大」 에 붙음
```

엉뚱한 글이 딸려 들어오면 확산 점수가 근거 없이 오른다.
겹침 하한을 **4쌍 → 7쌍**, 짧은 쪽 최소 길이 **8쌍**으로 올렸다.

## ★★절대금지 층 — 한국판에 없는 부분이다

일본 커뮤 상위권은 **국적·정치·연예인 두들기기**가 태반이다.
반응만 보고 세우면 상위 20개가 죄다 만들면 안 되는 것으로 찬다.
실측: 2,517건 중 **392건(15%)** 이 절대금지에 걸렸고, 그것들이 반응은 제일 컸다.

| 사유 | 무엇 |
|---|---|
| 혐오·국적 | 在日·嫌韓·嫌中·外国人犯罪·不法滞在 … **혐오 콘텐츠다. 채널이 끝난다** |
| 정치대립 | 정당·首相·議員·選挙 + **知事·市長·県議** |
| 실명범죄·불행 | 逮捕·訴訟·不倫·死亡 + **재난·대형사고**(事故·衝突·重体·搬送) |
| 성인 | エロ·水着·AV … |
| 실황·잡담 | 実況·本スレ·安価·配信·推し … |
| 창작물 | 漫画·イラスト·描いてみた … (남의 저작물) |

### 말끝만 다르면 그냥 통과한다 — 어간까지 내려 잡아라

실측에서 세 번 뚫렸다.

- `死亡事故` 만 막아 뒀더니 「作業員4人が**死亡**」(1002레스)이 1위로 올라왔다
- `死亡` 을 막았더니 「4人が特急列車と**接触し重体**」가 2위로 올라왔다
- `知事` 가 없어서 「兵庫県**斎藤知事**、人殺しコール」이 그냥 통과했다

**시트 맨 아래 '만들지 마라' 칸을 반드시 읽어라.** 반응 큰 게 거기 있다.

## ★앙케트 잡담이 반응으로 밀고 올라온다

ガルちゃん·小町 상위의 태반이 **앙케트형 잡담**이다. 코멘트가 크게 붙지만
사실이 하나도 없어 대본을 못 쓴다.

```
2人目を迷っています            ← 10위
接客してて思わず笑ったこと      ← 11위
「死ね」と言われたことありますか？ ← 14위
海外旅行に行ったことない人       ← 6위
```

**물음표가 없는 쪽이 더 많다** — 일본어는 체언으로 끊기 때문이다.
그래서 두 가지로 건다.

- 짧은 의문형(`22자 미만` + `？` 끝) → −0.40
- **나열형**: 짧고 · 숫자도 인용도 없고 · `人`·`こと`·`事`·`もの`·`話` 로 끝남 → −0.45

알맹이(`fit`) 가중을 한국판(0.40)보다 세게 **0.55** 로 둔 것도 같은 이유다.
일본 커뮤는 사고·사건 스레가 레스 수로 밀고 올라오는데 30초 안에 뒤집을 알맹이가 없다.

## 점수

```
score = (열기 + 확산 + 속도 + 결) × (1 + 0.55×알맹이) × (1 + 0.55×안전) × 기사보정
```

| 항목 | 뜻 |
|---|---|
| 열기 | 사이트 눈금 맞춘 반응량 (그 사이트 중앙값 대비 배수, 로그) |
| 확산 | **몇 계열에 동시에 떴나** — 이 헌터에서 제일 센 신호 |
| 속도 | 갓 올라왔는데 벌써 뜨거운가 |
| 결 | 여초·남초·지식층·뉴스에 걸쳐 떴나 |
| 알맹이 | 30초 안에 뒤집을 것이 있나 (−1~+1) |
| 안전 | 대전제(비난 금지)와 맞나 (−1~+1) |
| 기사보정 | 겹침 있으면 최대 +45%, 없으면 ×0.60 |

**마토메는 반응 수치가 없다.** 0 을 주면 사라지고 크게 주면 근거 없이 이긴다.
`MATOME_FLOOR = 0.55` — **혼자 뜨면 못 이기고, 다른 계열과 겹치면 확산으로 이기는** 값이다.

## 뉴스 교차확인 — 필요한 소스에만 건다

はてブ·ヤフコメ·5ch ニュース速報+ 는 **원본이 기사**라 물어볼 이유가 없다(`원본기사` 로 찍힌다).
ガルちゃん·小町·Togetter·마토메만 `news.yahoo.co.jp/search` 로 확인한다.

일본어는 띄어쓰기가 없어 한국판의 낱말 자르기를 그대로 못 쓴다.
**「」 인용 → 긴 한자 덩어리 → 가타카나 → 영숫자** 순으로 고유명사를 뽑는다.
`日本`·`女性`·`問題` 같은 흔한 한자말은 `GENERIC` 으로 뺀다.

## 쓰는 법

```
python ref_jpcomm/hunt.py                          # 17곳 → 상위 25 (약 40초)
python ref_jpcomm/hunt.py --no-news                # 빠르게 (4초)
python ref_jpcomm/hunt.py --show-blocked           # 절대금지로 뺀 것도 본다
python ref_jpcomm/hunt.py --only 生活・マナー論争,逆説・雑学
python ref_jpcomm/hunt.py --accum-hours 0          # 이번 것만 (누적 끄기)
```

- 결과: `ref_jpcomm/out/hunt_<시각>.md` + `_최신시트.md` + `_최신시트.json`
- 중복목록은 `ref_jpcomm/seen.json` (쇼피드 전용. 한국 채널과 나눈다)
- **하루 3~4번 돌려 쌓는다.** `--accum-hours 24` 가 기본값이다

### 시트에서 볼 것

- **맨 아래 '만들지 마라' 칸을 먼저 읽어라.** 반응 큰 게 거기 있다
- `기사` 열이 `❌0` 이면 만들지 마라. `10/0.09` 처럼 건수만 많고 겹침이 낮으면 딴 사건이다
- `커뮤` 열의 **계열 수**를 봐라. `(1계열)` 이면 한 커뮤 안에서만 도는 것이다
- `안전` 이 음수면 대전제 쪽을 다시 읽는다. **제목은 직접 읽는다** —
  "30초 안에 뒤집을 알맹이가 있나"는 스크립트가 못 판단한다
