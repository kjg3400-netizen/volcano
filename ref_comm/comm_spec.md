국내 커뮤니티 10곳의 실시간 인기글을 긁어 **진짜 이슈몰이 될 것**만 세운다.

조사·실측 2026-08-20.

## 무엇이 자동화되고 무엇이 안 되나

| 단계 | 상태 |
|---|---|
| 1. 발굴 — 커뮤 10곳 인기글 330여 건 | **자동** (`hunt.py`, 1.7초) |
| 2. 사이트별 눈금 맞추기·교차커뮤 묶기·점수 | **자동** (`hunt.py`) |

## ★커뮤는 소재가 아니라 레이더다

이게 이 도구의 전제이고, 경제 헌터와 가장 다른 점이다.

네이버 기사는 **매체가 책임지는 보도**다. 커뮤 글은 **개인이 쓴 미검증 주장**이고
남의 저작물이다. 커뮤 글을 그대로 대본으로 옮기면 두 가지가 한꺼번에 터진다 —
오보가 되고, 베끼는 게 된다.

그래서 파이프라인이 이렇게 짜여 있다.

```
커뮤 10곳  →  뭐가 터졌나 (레이더)
                ↓
          네이버 기사 교차확인   ← 여기서 검증된 것만 통과
                ↓
          기사를 소재로 대본     ← 사실관계는 전부 기사에서
                ↓
          커뮤 반응은 훅으로만   (comm_context.txt)
```

`brief.py` 는 **일부러 커뮤 본문을 안 긁는다.** 고른 사건을 보도한 네이버 기사를
찾아 검증된 경제 브리퍼에 넘긴다. 커뮤에서 가져오는 건 '어디서 얼마나 터졌나' 하나뿐이다.

캡쳐를 쓸 거면 **닉네임·프로필 사진·커뮤 로고를 가린다** (볼케이노 공통 규칙).

## ★조용히 틀리는 곳 — 다섯 군데

### 1. 태그 안에 줄바꿈이 섞여 있다 (가장 크게 물린 곳)

```html
<li class="li
     li_best2_pop0 ...">          ← 펨코
<tr class="ub-content
     us-post thum" ...>            ← 디시
```

`<li class="li li_best2` 같은 패턴이 **오류 없이 그냥 안 잡힌다.**
실측: 펨코 0건, 아카라이브 0건, 디시는 49건 중 2건.
**사이트가 죽었거나 차단당한 줄 알기 딱 좋은데 아니다.**

`hunt.py` 의 `norm_ws()` 가 파싱 전에 `\s+ → ' '` 로 뭉갠다. **빼면 안 된다.**

> ※ 이 함정은 눈으로도 안 보인다. HTML 을 덤프해 보는 스크립트가 대개
> 보기 좋으라고 공백을 먼저 뭉개기 때문이다 — 그래서 덤프에는 멀쩡히 보인다.
> 실제로 그렇게 한 번 속았다.

### 2. 사이트마다 눈금이 딴판이다

| | 추천 | 댓글 | 조회 |
|---|---|---|---|
| 디시 실베 | 890 | — | 16,441,168 |
| 클리앙 | 1 | 0 | — |
| 더쿠 | — | 651 | 16,526 |

절대값을 섞어 세우면 **디시 글이 목록을 독식한다.**
`normalize()` 가 **그 사이트 이번 수집분의 중앙값 대비 몇 배**로 환산한다.
가중치는 댓글 1.0 · 추천 0.7 · 조회 0.45 — 조회는 낚시 제목에도 붙고
추천은 커뮤 성향을 많이 탄다.

### 3. 공지·이벤트가 상위를 독식한다

첫 실행의 1·2·3위가 전부 더쿠 공지였다 (`◤더쿠 이용 규칙◢`,
`비밀번호 변경 권장`, `공지가 길다면…`). 반응이 크게 붙어 있어 점수로는 못 이긴다.
`NOTICE` 낱말 목록 + 사이트별 공지행 필터(`<tr class="notice">`, 번호 자리가 숫자인지)로 건다.

### 4. 검색어에 커뮤 말머리가 섞이면 기사를 못 찾는다

```
[좆됨] 법인 파산, 반년 만에 코로나 1년치 추월
  → '좆됨 법인 파산 반년'   → 0건
  → '법인 파산 반년 만에'   → 10건, 바로 그 기사
```

`news_query()` 가 `[...]` `(...)` 말머리 · 확장자 · 자음(ㅋㅋ ㄷㄷ) · 은어를 떤다.

### 5. 네이버는 몰아치면 빈 껍데기를 준다

동시 4건 이상으로 검색하면 결과 없는 JS 껍데기(30KB 남짓)가 온다.
**진짜 0건과 구별이 안 된다** — 그래서 기사가 있는데도 "기사없음"으로 찍힌다.
동시 3건으로 눌러 두고, 응답이 80KB 미만이면 한 번 쉬었다 다시 묻는다.

## ★한국어 조사 때문에 두 군데가 한꺼번에 망가진다 (2026-08-21)

같은 뿌리에서 나온 함정 둘이다. **낱말을 그대로 맞대면 안 된다** —
조사·어미가 붙어 `동물` ≠ `동물권`, `경찰이` ≠ `경찰` 이 되고,
커뮤 제목의 말투(`하자고`·`했다네`)가 분모만 키운다.

### ① 검색어를 좁히면 못 찾는다

```
새덕후) 경찰이 동물 보호법 위반으로 조사 하자고 했다네?
  '새덕후 경찰이 동물 보호법'  → 0건
  '새덕후'                    → 10건, 전부 그 사건
```

`news_queries()` 가 **넓은 것 → 고유명사 하나** 순으로 사다리를 탄다.
고유명사는 커뮤 제목 **맨 앞**에 온다. '가장 긴 낱말'로 고르면 안 된다 —
조사가 붙어 길어진 `위반으로`·`3위까지`·`100m` 를 집는다. 조사를 떼려고도 하지 마라
(`고양이` 가 `고양` 이 된다). 붙은 채로 물어도 검색엔진이 알아서 나눈다.

### ② 겹침을 낱말 교집합으로 재면 다 버린다

같은 사건 기사 10건이 **전부 0.12** 로 나와 문턱 0.20 에 걸려 버려질 뻔했다.
`title_overlap()` 은 셋 중 가장 큰 값을 쓴다 —
낱말 교집합 · 글자쌍 포함도 · **고유명사 적중(0.55, 제일 세다)**.
고치니 같은 기사가 0.12 → **0.55** 가 됐다.

### ③ 차단을 '기사 없음' 으로 오진하지 마라

`brief.py` 가 네이버 403 을 삼키고 "기사를 못 찾았다"고 했다.
**기사는 그대로 있었고 검색이 막혔을 뿐이다.** 차단이면 그렇게 말하고 멈춘다 —
사장님이 "이 소재는 기사가 없구나" 하고 버리면 안 된다.

> 오늘 같은 실패가 네 번 났다(파서 0건·검색 0건·겹침 0.12·차단 오진).
> **전부 "조용히 틀린" 것들이다.** 0 이 나오면 값을 믿기 전에 왜 0 인지부터 봐라.

## ★건수가 아니라 '겹침'으로 판정한다

뉴스 교차확인에서 건수만 보면 속는다.

```
싱글벙글 절이나 교회를 습관적으로 다니지 마십시오
  → 기사 7건  ← 전부 무관 (북카페 서평 등)
  → 겹침 0.00
```

겹침 = 커뮤 제목 낱말 중 기사 제목에도 있는 비율. **0.20 미만은 기사 없음과 같이 친다.**
이 문턱을 넣기 전에는 저 교회 글이 3위였다.

점수 반영은 이렇다 — 겹침이 있으면 최대 +55%, 없으면 ×0.55.
**버리지는 않는다.** 언론이 아직 안 받은 특종일 수도 있어 사람이 시트에서 본다.

## 갈래 — 경제·정치는 뺀다

경제·정치는 다른 채널에서 다룬다(사장님 지시 2026-08-20). `--drop 정치,경제` 가 기본값이다.

| 갈래 | 오늘치 | 결 |
|---|--:|---|
| 이슈 | 185 | 사건·논란·사연. 물량이 제일 많다 |
| 유머 | 99 | 절반은 만화·짤이라 못 쓰고, 절반은 알맹이가 있다 |
| **잡학** | 30 | `~하는 이유` · `~의 비밀`. **뇌전구와 결이 제일 잘 맞는다** |
| 정치 | 22 | 뺀다 |
| 경제 | 10 | 뺀다 |
| 연예·스포츠 | 11 | 남겨 두고 눈으로 고른다 |

### ★갈래로 자르지 마라 — '알맹이'로 잘라라

**유머라서 못 쓰는 게 아니라 알맹이가 없어서 못 쓰는 것이다.**
잡학에도 알맹이 0.00 이 수두룩하고(`싱글벙글 절이나 교회를 다니지 마십시오`),
유머판에도 +0.30 이 있다(`역대급 경제위기라는 이탈리아 근황`,
`남편 김치찌개 끓여줘서 욕먹던 사람 대반전`).

그래서 경제·정치만 빼고 나머지는 다 남긴 뒤 `fit`(알맹이) 로 세우고,
시트에 갈래를 적어 **사람이 눈으로 고른다.** `--only 잡학` 으로 좁힐 수는 있다.

창작물(만화·그림·제작기)은 반응이 크게 붙지만 못 쓴다 — `MADE` 로 감점한다.
★확장자 놀이를 `...manhwa` 처럼 길게 붙이면 `EXT` 만으로는 못 잡는다.

**★디시 실베·힛갤이 이미 필터 노릇을 하고 있다. 그 앞단(원본 갤러리)을 긁지 마라.**

※ 갤러리 id 는 `search.dcinside.com/gallery/q/<검색어>` 로 찾는다.
정식갤은 `board/lists`, 마이너갤은 `mgallery/board/lists` 다 — **바꿔 쓰면

## ★펨코는 `/best` 만 긁는다 — 일반 게시판을 건드리면 IP 가 막힌다

`/mystery` 같은 일반 게시판을 몇 번 두드렸더니 **HTTP 430 `에펨코리아 보안 시스템`**
이 뜨고, 그때부터 **`/best` 까지 같이 막혔다**(2026-08-21 실기).

- 포텐터짐(`/best`)은 **이미 전 게시판을 모아 준다** — 유머·움짤·야구·영화·미스터리가
  한 목록에 섞여 나오고 `category` 로 어느 게시판인지 알 수 있다. 보드를 더 긁을 이유가 없다
- 게다가 행 클래스에 **정치 여부가 박혀 있다** (`li_best2_politics0/1`) — 제목으로 추측할 필요가 없다
- 차단은 IP 단위라 코드로 못 푼다. **쉬었다 다시 하는 수밖에 없다**

`get_text()` 가 403·429·430 과 차단 문구를 `Blocked` 로 올리고,
시트에 `⛔ 차단` 으로 찍는다. **`⚠ 0건`(구조 변경) 과 반드시 구별해서 봐라 —
대응이 정반대다.** 구조가 바뀐 거면 파서를 고쳐야 하고, 차단이면 손대지 말고 쉬어야 한다.

## ★한 번만 돌리면 놓친다 — 누적이 답이다

실시간 베스트는 빨리 갈린다. **54분 만에 전체 38%가 바뀌었다**(실측 2026-08-21).

| 커뮤 | 54분 뒤 갈린 비율 |
|---|--:|
| 아카라이브 | 7% |
| 디시 실베 | 10% |
| 더쿠 | 15% |
| 인벤 | 36% |
| **루리웹** | **97%** |
| **개드립** | **100%** |

루리웹 `/best` 와 개드립은 **한 시간이면 목록이 통째로 바뀐다.**
한 번 돌리면 그 순간 걸린 것만 보게 되고, 잡학처럼 드문 갈래는 그래서 30건밖에 안 잡힌다.

`--accum-hours 24`(기본값)가 지난 실행의 `out/raw_*.json` 을 합친다.
**하루 3~4번 돌리면 풀이 서너 배가 된다.** 같은 글은 링크로 묶고 반응이 큰 쪽을 남긴다.

### 링크는 정규화해서 묶는다

목록 링크에는 정렬·탭·페이지 파라미터가 붙는다
(루리웹 `?m=humor_only&t=now`, 디시 `&_dcbest=1&page=1`, 보배 `&vdate=`).
그대로 열쇠로 쓰면 **같은 글이 매번 새 글로 쌓인다.**
`canon_link()` 가 글을 가리키는 파라미터(`no`·`No`·`id`·`code`…)만 남긴다.

> ※ 위 교체율은 정규화 뒤에 잰 값이라 진짜다. 처음엔 파라미터 탓인 줄 알았는데
> 아니었다 — 루리웹·개드립은 실제로 글 번호가 다 갈린다.

## 점수

```
score = (열기 + 확산 + 속도 + 결) × (1 + 0.40 × 적합도) × 기사보정
```

| 항목 | 뜻 |
|---|---|
| 열기 | 사이트 눈금 맞춘 반응량 (로그) |
| **확산** | **몇 개 커뮤에 동시에 떴나 — 이 헌터에서 제일 센 신호** |
| 속도 | 갓 올라왔는데 벌써 뜨거운가 |
| 결 | 남초·여초·시사에 걸쳐 떴나 |
| 적합도 | 제목의 뇌전구 적합성 (−1 ~ +1) |
| 기사보정 | 겹침 있으면 최대 +55%, 없으면 ×0.55 |

**적합도는 보조지만 커뮤에서는 경제보다 중요하다.** 커뮤 인기글의 태반이
짤·잡담·팬질·성인물이라 반응만으로 세우면 상위 20개가 죄다 못 쓸 것으로 찬다.

- 감점: 확장자(`.jpg` `.gif` `.eu…` — **아무 글자나 붙이므로 정규식으로 잡는다**),
  잡담·질문·투표, 팬질(직캠·컴백·앨범), 성인(후방·약후), 스포츠 실황, 정치 인물·정당
- 가점: 반전(알고보니·불구·오히려·이유), 최초/최다/기록, 사건성(적발·판결·폭로),
  정보(연구·조사·통계), 숫자

사건 묶기는 경제(0.32)보다 살짝 눅인 **0.30** 이다 — 커뮤는 퍼나르면서
제목을 조금씩 바꾼다.

## 쓰는 법

```
python ref_comm/hunt.py                    # 10곳 → 상위 25 (약 45초)
python ref_comm/hunt.py --top 40
python ref_comm/hunt.py --no-news          # 뉴스 확인 끄고 빠르게 (2초)
python ref_comm/hunt.py --min-fit -0.2     # 짤·잡담을 더 세게 거른다
python ref_comm/hunt.py --group-th 0.26    # 사건 묶는 세기

python ref_comm/brief.py --pick 2          # 2번 골라 소재 준비
python ref_comm/brief.py --pick 2 --dry    # 어느 기사가 잡히는지만 본다
python ref_comm/brief.py --pick 2 --with-siblings
```

- 결과: `ref_comm/out/hunt_<시각>.md` (사람이 보는 시트) + `.json`
- 중복목록은 **경제 헌터와 같은 `ref_econ/seen.json`** 을 쓴다. 같은 채널이니 나눌 이유가 없다.
  회차를 낼 때마다 `python ref_econ/seed_seen.py` 를 한 번 돌린다

### 시트에서 볼 것

- `기사` 열이 `❌0` 이면 **만들지 마라.** 커뮤 안에서만 도는 미검증 글이다
- `기사` 열 `10 / 0.09` 처럼 건수는 많은데 겹침이 낮으면 **딴 사건**이다
- `커뮤` 열에 성향이 다른 판이 섞여 있으면(더쿠·펨코) 크게 터진 것이다
- **제목은 직접 읽는다.** "30초 안에 뒤집을 알맹이가 있나"는 스크립트가 못 판단한다
