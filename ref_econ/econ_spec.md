# 경제 뇌전구 — 소재 발굴 자동화

네이버 뉴스에서 **실제로 반응이 붙은** 경제 기사를 찾아 점수순으로 세운다.
사장님이 손으로 하시던 "뒤져서 될 만한 것 고르기"를 대신한다.

조사·실측 2026-08-20.

---

## 무엇이 자동화되고 무엇이 안 되나

| 단계 | 상태 |
|---|---|
| 1. 발굴 — 경제 기사 300여 건 긁기 | **자동** (`hunt.py`, 1.5초) |
| 2. 반응 실측 — 댓글·감정반응 | **자동** (`hunt.py`, 75초) |
| 3. 점수·사건묶기·중복제거 | **자동** (`hunt.py`) |
| 4. **고르기** | 사람 — 시트 보고 번호 하나 |
| 5. 소재 준비 — 본문·사진·시트 | **자동** (`brief.py`) |
| 6. 대본 → 렌더 → 납품 | 기존 뇌전구 파이프라인 |

4번을 자동으로 넘기지 않는 이유는 셋이다 — 오보를 그대로 만들면 채널이 다치고,
같은 소재를 두 번 만들 수 있고, 회차마다 이미지·TTS 실비가 나간다.
대신 **번호 하나로 끝나게** 만들어 두었다.

## ★네이버 API 함정 — 전부 오류 없이 조용히 틀린다

### 1. 랭킹 페이지의 `sectionId` 는 무시된다

```
popularDay.naver?sectionId=101   ← 경제만 나올 것 같지만
popularDay.naver?sectionId=100   ← 정치로 바꿔도
popularDay.naver                 ← 아예 빼도
```
**셋 다 똑같은 375건**이 온다. 전 섹션 언론사별 랭킹이다.
이걸 경제 소재로 알고 쓰면 결과가 죄다 정치·사회 기사로 나온다(실제로 그랬다).

`SECTION_RANKING_NEWS?sid=101` 도 마찬가지다 — `sid` 를 100 으로 바꿔도 **83건이 완전히 동일**.

**섹션이 제대로 먹는 건 이 둘뿐이다.**

| 경로 | 검증 |
|---|---|
| `news.naver.com/section/101` | 경제만 나온다 |
| `section/template/SECTION_ARTICLE_LIST?sid=101` | sid=101 과 100 의 겹침 **0건** |

※ `SECTION_ARTICLE_LIST_FOR_LATEST` 는 빈 응답(84바이트)만 돌려준다. 쓰지 마라.

그래서 구조가 이렇게 된다 — **후보 풀은 섹션 목록에서만** 만들고,
전체 랭킹은 "전 섹션 통틀어 순위에 들었다"는 **가산점**으로만 쓴다.

### 2. 페이지 인코딩이 경로마다 다르다

| 경로 | 인코딩 |
|---|---|
| `main/ranking/*.naver` (구형) | **EUC-KR** |
| `news.naver.com/section/*` | UTF-8 |

`r.encoding = "utf-8"` 로 못박으면 한글이 통째로 깨진다. 오류는 안 난다 —
**제목이 깨지고 "3시간전" 파싱이 조용히 실패해 경과시간이 전부 비게 된다.**
`get_text()` 가 헤더 charset → meta charset → utf-8 → cp949 순으로 판정한다.

### 3. 감정반응 세트가 바뀌었다 — `화나요` 는 이제 없다

지금 나오는 건 **5종뿐**이다.

| 키 | 라벨 |
|---|---|
| `useful` | 쏠쏠정보 |
| `wow` | 흥미진진 |
| `touched` | 공감백배 |
| `analytical` | 분석탁월 |
| `recommend` | 후속강추 |

옛 `like`/`angry`/`sad` 는 응답에 안 온다. **'화나요 비율로 논쟁도를 잰다'는 설계는 항상 0 이 나온다.**
경제 뇌전구는 `쏠쏠정보+흥미진진+분석탁월` 비중(시트의 `정보%`)이 높은 쪽이 결에 맞는다.

### 4. 목록의 댓글수 자리는 비어 있다

```html
<a class="sa_text_cmt _COMMENT_COUNT_LIST" style="display:none"
   data-object-id="news057,0001964488"></a>
```
JS 가 채우는 자리라 HTML 만 긁으면 못 얻는다. 기사마다 API 를 따로 불러야 한다
(그래서 실측에 75초가 든다).

### 5. `sa_text_datetime` 은 `<span>` 이 아니라 `<div>` 다

```html
<div class="sa_text_datetime is_recent"><b>18분전</b></div>
```
`</span>` 으로 닫는 정규식을 쓰면 시간이 안 잡히고 **속도 점수가 통째로 무효**가 된다.

### 6. ★`--hours` 는 거짓말이다 — 진짜 한계는 `--pages` 다

`--hours 36` 이 기본값이라 "최근 36시간을 본다"고 착각하기 쉽다. 아니다.
섹션 목록은 **페이지 수만큼만** 거슬러 올라가므로, 그보다 옛 기사는 애초에 안 긁힌다.

| `--pages` | 기사 | 실제 커버 | 실측 시간 |
|--:|--:|--:|--:|
| 8 (옛 기본) | 333 | **6~7시간** | 73초 |
| 16 (지금) | 620 | **10시간** | 135초 |

경제 섹션은 기사가 많이 쏟아져서 8장이면 6시간밖에 못 간다.
하루 3번(06 / 13 / 20시) 돌리면 실행 간격이 7·7·10시간이라 **6시간치로는 사이가 빈다** —
20~23시에 나온 기사가 어느 실행에도 안 잡혔다.

**그냥 놓치는 게 아니라 큰 걸 놓친다.** 8장으로 돌린 시트에는
`SK하이닉스 성과급 60% 주식 지급`(댓글 694 · 32개 매체, 그날 압도적 1위)이 없었다.
10시간 전 기사여서다. 16장으로 올리자 바로 1위로 올라왔다.

`hunt.py` 가 이제 **긁힌 범위를 매번 찍고** 9시간 미만이면 경고한다.
조용히 틀리던 걸 눈에 보이게 만든 것이라 지우지 마라.

### 7. ★`/cluster/` 는 사건 묶음이 아니라 주제 피드다

목록에 `href="/cluster/c_202608201600_00000001/"` 이 붙어 있어 "네이버가 같은 사건을
묶어 두었구나" 싶지만 아니다. 열어 보면 **한 클러스터에 132건**이 들어 있다 —
가계부채 관련 기사를 몇 달치 모아 둔 주제 피드다.

이걸 믿고 묶었더니 `삼성전자 150조 주주환원` 묶음에 가계대출 기사가 딸려 들어와
**사진 후보 7장 중 4장이 엉뚱한 은행 사진**이 됐다(실측으로 잡았다).
실행일에 잡힌 클러스터 10개가 **전부** 60건을 넘었다. 조회 값만 치르고 얻는 게 없어
페이지 조회는 뺐다.

**사건 묶기는 제목 글자 bigram 유사도로 한다.**

## 사건 묶기 — 왜 이렇게 짰나

한 사건을 매체 10곳이 쓰면 후보 목록이 그 사건 하나로 도배된다.

- **포함도**(겹침 ÷ 짧은 쪽)를 쓴다. 자카드는 매체마다 제목 길이가 달라 너무 짜다
- **겹치는 글자쌍 5개 미만이면 0** — 짧은 제목이 긴 제목에 우연히 들어가는 걸 막는다
- **대표하고만 비교하는 그리디**다. 전체쌍 union-find 로 하면 A-B, B-C 가 이어져
  **상관없는 45건이 한 덩어리**가 된다(실측)
- 기본 문턱 `0.32`. `--group-th` 로 조절한다

한계는 정직하게 적어 둔다 — 매체마다 말이 아주 다른 경우
(`세입자 53만원 내면 집주인 73만원` ↔ `정부가 전세금 관리, 집주인에 이자 지급`)
는 여전히 따로 뜬다. 임계값을 0.26 까지 낮춰도 안 붙고, 더 낮추면 오병합이 난다.
**시트에서 두 줄로 보이는 정도라 치명적이지 않다.**

## 점수

```
score = (열기 + 속도 + 확산 + 랭킹 + 결) × (1 + 0.40 × 적합도)
```

| 항목 | 뜻 |
|---|---|
| 열기 | 사건 전체 댓글·반응 수 (로그) |
| 속도 | 댓글 ÷ 경과시간 — 갓 올라왔는데 벌써 뜨거운 것을 잡는다 |
| 확산 | 몇 개 매체가 받아썼나 |
| 랭킹 | 전 섹션 랭킹 진입 (경제 기사가 여기 들면 큰 사건이다) |
| 결 | 쏠쏠정보·흥미진진 쪽으로 기울었나 |
| 적합도 | 제목의 역설·숫자·최초/최다 패턴 (−1 ~ +1) |

**적합도는 보조다.** 사장님이 원하시는 건 "실제로 반응 좋은 것"이라 실측이 주(主)고,
제목 패턴은 ±40% 만 흔든다.

### ★채널 실적 가중치 — 네이버 반응만 믿으면 틀린다

네이버에서 반응이 좋아도 **이 채널에서 안 먹히는 꼴**이 있다.
2026-08-20 에 숏단지 15편을 실측해서 알았다.

| 꼴 | 편수 | 중앙 조회 | 배수 |
|---|--:|--:|--:|
| 한국 vs 해외 | 1 | 16,354 | ×1.60 |
| 인물·거액 | 3 | 8,102 | ×1.48 |
| 증시·기업 | 4 | 4,024 | ×0.99 |
| 제도·거시 | 1 | 2,409 | ×0.90 |
| 사연 | 2 | 2,658 | ×0.86 |

(성숙 11편 · 채널 중앙 4,119회 · 48시간 지난 편만)

**첫 추천이 이걸 몰라 틀렸다.** 전세 안심신탁을 네이버 `정보% 95` 만 보고 1순위로 밀었는데,
제도·거시는 이 채널 최하위 꼴이었다. 같은 계열인 `자진 퇴사해도 실업급여` 가
실제로 하위였다.

- 가중치는 `learn.py` 가 채널을 받아 계산해 `channel_fit.json` 에 쓴다
- **표본이 적을 때 비율을 그대로 곱하면 과적합이다.** 1편짜리 배수 3.97 을
  그대로 쓰면 그 꼴이 상위를 독식한다. `n/(n+3)` 로 1.0 쪽으로 당기고 `[0.7, 1.6]` 로 자른다.
  편이 쌓이면 축소가 저절로 풀린다 — **회차를 낼 때마다 다시 돌리면 날카로워진다**
- 시트에 `네이버 점수 × 채널 배수 = 최종` 을 다 보여 준다. 배수만 보고 고르지 말라는 뜻이다
- `--no-fit` 로 끄면 네이버 반응만으로 세운다

#### 꼴 분류는 순서가 결과를 바꾼다 (`shapes.py`)

`제도·거시 → 한국vs해외 → 사연 → 인물·거액` 순으로 먼저 맞는 것을 쓴다. 두 번 밟았다.

- `한 달 만에 결혼 자금 2천 날리고 멘붕`(1,389회)이 **'달 만에'** 에 걸려 인물·거액으로 새면
  그 묶음 중앙이 8,102 → 7,375 로 내려앉는다 → **사연을 인물·거액보다 먼저 본다**
- `글로벌 IB가 화답`(그냥 증시 기사)이 **'글로벌'** 로 한국vs해외 ×1.6 을 받아 1위로 올라왔다
  → 두루뭉술한 낱말(글로벌·세계·해외)을 빼고 **나라 이름과 자리 뺏는 동사만** 남겼다.
  실적을 낸 건 `중국이 52척 싹쓸이` 같은 구도지 낱말이 아니다
- `주주`·`배당` 을 인물·거액에 넣으면 `삼성이 주주한테 300조`(증시 건)를 끌어온다

### 갈래

네이버는 전부 '경제' 한 덩어리로 준다. 증시 기사와 전세 제도 기사가 같은 칸에 섞여
있으면 고르기 어려워 시트에 갈래를 붙인다 — **증시 · 부동산 · 기업 · 제도 · 거시 · 생활**.
낱말 사전이라 완벽하진 않고 `기타`도 나온다. 점수에는 영향을 주지 않는 **표시용**이다.

적합도 사전은 납품 이력에서 뽑았다 — 역설(`~는데`·`불구`·`오히려`),
최초/최다(`최다`·`처음`·`앞질`·`돌파`), 급변(`반토막`·`무너`·`적자`), 숫자.
반대로 `[표]`·`[특징주]`·`코스피`·`마감`·`시황` 같은 하루살이 시세 기사는 깎는다.

## 쓰는 법

```
python ref_econ/hunt.py                      # 경제, 상위 25
python ref_econ/hunt.py --top 40 --hours 12
python ref_econ/hunt.py --sid 101,105        # 경제 + IT/과학
python ref_econ/hunt.py --min-comments 50

python ref_econ/brief.py --pick 3                  # 3번 골라 소재 준비
python ref_econ/brief.py --pick 3 --with-siblings  # 같은 사건 다른 매체 사진까지
python ref_econ/brief.py --url <네이버 기사 링크>

python ref_econ/seed_seen.py                 # 납품 이력을 중복목록에 반영
python ref_econ/seed_seen.py --list

python ref_econ/learn.py                     # 채널 받아 실적 가중치 다시 계산
python ref_econ/learn.py --show              # 지금 쓰이는 배수만 보기
python ref_econ/learn.py --cached            # 다시 안 받고 캐시로 계산
```

- 결과: `ref_econ/out/hunt_<시각>.md` (사람이 보는 시트) + `.json`
- **`out/raw_<시각>.json` 은 실측 캐시다.** 점수·묶음만 손볼 때는
  `--from-raw` 로 다시 굴리면 75초를 안 쓴다
- `brief.py` 는 `work_econ_<날짜>_<기사id>/` 를 파고 본문·사진·`_sheet_real.jpg` 를 만든다.
  **시트는 반드시 눈으로 본다** — 규격(1184×880)에 못 미치는 사진이 섞여 있다

### 중복 방지

`seen.json` 이 이미 만든 회차를 막는다. 납품 폴더(`볼케이노 완성본`) 파일명에서
제목을 긁어 오므로, 회차를 낼 때마다 `seed_seen.py` 를 한 번 돌리면 된다.
제목 토큰이 45% 이상 겹치면 후보에서 뺀다.

## 채널 진단 — 2026-08-20 실측 (숏단지, 15편 8일차)

3편으로 늘릴지 판단하려고 채널을 직접 받아 봤다. `work_ch_sudanjip/` 에 스크립트가 있다.

- **구독 20명 · 편당 중앙 4,199회.** 구독자가 만들 수 있는 수가 아니다 →
  조회가 사실상 전부 **쇼츠 피드(탐색)** 에서 온다. "초기라 안 나오는 것"이 아니라
  알고리즘은 이미 밀어주고 있다
- **업로드 시각은 성과를 안 가른다.** 오전 8시 5편 중앙 4,119 / 저녁 17시 6편 중앙 4,664.
  두 번째 편이 안 떨어진다 = 수요가 안 찼다 → **편수를 늘릴 여지가 있다**
  (평균만 오전이 높은데 LNG선 16,354 한 편 때문이다. 평균에 속지 마라)
- **08-16 에 이미 3편을 해봤다.** 22시 편이 3,928회로 중앙값 수준 —
  세 번째가 앞의 둘을 갉아먹지 않았다
- **성과를 가르는 건 꼴이다.** 최고와 최저가 7배 (16,354 ↔ 2,409).
  잘 되는 편은 주체가 뚜렷하고 금액이 크다(`중국이 52척 싹쓸이`, `455억 번 회장님`).
  안 되는 편은 주체가 흐릿하다(`가계 빚 2000조`, `실업급여 제도`)
- **약점은 구독 전환이다.** 79,900회에 구독 20명 = 4,000회당 1명. 좋아요율 0.3~0.8%.
  조회는 나오는데 사람이 안 남는다. 소재가 아니라 마지막 컷·채널 정체성 쪽 문제다

**★프록시 지표만 보고 추천하지 마라.** 채널 실적은 `yt-dlp` 로 언제든 받아볼 수 있다.
