# 영어학습형 (배치 100편) — 실측 기록

표본 1편 프레임 픽셀 실측 + 전사 대조, 2026-08-21.
원자료는 `sample/`. 아직 **빌더도 헌터도 없다** — 이 문서가 조사 결과 전부다.

## 왜 이걸 조사했나

사장님이 `히토미다운\화면 캡처 2026-08-21 225216.jpg` 를 주시며
"저기 안에 있는 것처럼 100개 소재 뽑아서 업로드까지 다 자동" 이 되냐고 물으셨다.
캡처는 `001_` ~ `099_` 번호가 붙은 mp4 100편 목록이었고, 표본 1편을 받아 뜯어봤다.

**결론: 된다. 그리고 이 갈래만 된다.** 이유는 아래 "왜 100편이 되나".

## ★내가 두 번 틀렸다 — 같은 실수를 하지 마라

1. 캡처만 보고 **잡학·지식형**이라 단정했다. 제목이 `듀오링고로 배운 일본어의 최후`
   `북한에서 ~하는 법` 이라 그렇게 읽혔다. **영어 학습 채널이었다.**
2. 정지 이미지 슬라이드쇼로 봤다. **영상 클립 재포장이다.**

둘 다 **표본 mp4 를 열어 보기 전에** 내린 판단이었다. 캡처 해상도가 202×263 이라
글자가 안 읽히는데도 넘겨짚었다. 표본을 받고 나서야 뒤집혔다.

## 한 줄 요약

**영어 원본 클립(스탠드업·인터뷰)에 [한국어+영어 이중 자막]을 얹고, 핵심 표현을
노랗게 칠해 팝업 카드로 뜻을 붙이고, 마지막에 [오늘의 표현] 표로 정리한다.**

앞뒤에 한국어 TTS 나레이션이 **딱 두 줄** 붙는다. 가운데는 원본 영어 소리 그대로다.

## 표본

| | |
|---|---|
| 파일 | `sample/ref_bobbylee_406x720.mp4` |
| 규격 | 406×720 · 24fps · 53.7초 · 10.0MB |
| 소재 | Bobby Lee 스탠드업 (Laugh Factory 워터마크가 화면에 남아 있다) |
| 화면 제목 | `필터 없는 아빠` / `아침 인사 수준` |
| 출처 표기 | `출처: Bobby Lee` |

★**이건 카카오톡으로 받은 압축본이라 1080×1920 이 아니다.**
아래 환산값은 ×2.667 한 것이고 **±3px** 로 봐야 한다.
글꼴은 이 해상도로는 자면 대조가 안 돼 **아직 미확정**이다.
원본 1080×1920 을 한 편 받으면 그때 확정한다.

### 색

| | |
|---|---|
| 노랑 (제목 2줄 · 강조어 · 팝업 박스) | `#FAD134` — RGB(250,209,52) |
| 흰색 | `#FCFCFC` |
| 오늘의 표현 표 배경 | RGB(21,49,43) 진한 청록 · 테두리는 밝은 녹색 |

★**노랑이 세 군데에 같은 값으로 쓰인다** — 제목 2줄, 자막 강조어, 팝업 박스.
매일일보형처럼 노랑이 둘로 갈리지 않는다.

### 자막 — 밴드 **안쪽** 아래에 2줄

| 줄 | 내용 | 꼴 |
|---|---|---|
| 위 | 한국어 | 흰색 + 핵심어만 노랑 |
| 아래 | 영어 | 흰색 **이탤릭** + 같은 자리 노랑 |

두 줄이 **1:1 로 맞물린다** (`편집 기능이 아예 없어요` / `They have no editing system`).
노랑이 칠해지는 자리가 곧 그 컷에서 가르치는 표현이다.

### 팝업 카드 — 강조어가 나올 때만 뜬다

밴드 **바깥**, 출처 줄 아래. 위에 노란 박스로 영어 표현, 아래 어두운 박스로 한국어 뜻.
표본에서는 t=8·32·44s 세 번 떴다. 강조어가 없는 컷에는 안 뜬다.

### ★오늘의 표현 표는 한 줄씩 쌓인다

t=50s 에 9줄, t=53s 에 12줄. **한 번에 안 뜬다.**
빌더가 줄마다 등장 시각을 가져야 한다 — 이걸 놓치면 마지막 4초가 정지 화면이 된다.

## 소리 구조 — 나레이션은 두 줄뿐이다

```
0.0~2.0s    [한국어 TTS]  인트로 한 줄 (제목을 풀어 읽는다)
2~48s       [원본 영어]   클립 소리 그대로
~50s        [한국어 TTS]  아웃트로 한 줄 (표로 넘기는 말)
50~53.6s    무음 + 오늘의 표현 표
```

음량은 0~50s 내내 -12 ~ -28 dBFS 로 이어지고 51s 부터 완전 무음이다.

★**TTS 가 편당 두 줄이다.** 100편이면 200줄이라 타입캐스트 동시 2건 상한에
거의 안 걸린다. 뇌전구·축구형과 견주면 TTS 비용·시간이 사실상 없는 셈이다.

## ★★왜 이 갈래만 100편이 되나 — 전사 하나에서 다 나온다

칩칩·축구·골프는 내가 프레임을 눈으로 보고 자막을 **지어내야** 한다. 그래서 편당 시간이 든다.
여기는 원본이 이미 말을 하고 있고, 그걸 **받아쓰기만** 하면 된다.

| 화면 요소 | 어디서 나오나 | 사람 필요? |
|---|---|---|
| 영어 자막 | Whisper 전사 = 그게 곧 영어 자막 | ✗ |
| 한국어 자막 | 그 줄의 번역 | ✗ |
| 노란 강조 | 전사에서 구동사·숙어를 고름 | ✗ |
| 팝업 카드 | 고른 표현 + 뜻 | ✗ |
| 오늘의 표현 표 | 고른 것들 누적 | ✗ |
| 나레이션 2줄 | 제목에서 파생 | ✗ |
| 제목 2줄 | LLM | ✗ |

### 실측으로 확인했다 — 12/12

완성본 마지막 표에 실린 표현 12개를 Whisper 전사와 대조했다.

```
no filter · editing system · whatever they think · look ugly · horrible
go outside · made me · used to bring · secrets · dark · front lawn · only had one piece

전사에 문자 그대로 있는 것: 12개 / 12개
```

**하나도 안 틀렸다.** 사람이 영상을 보고 고른 게 아니라 전사에서 뽑은 것이다.
이 대조가 "된다" 의 근거 전부이니, 의심되면 `sample/transcript_raw.json` 로 다시 해 봐라.

## ★조용히 틀리는 곳 — 둘 다 실기로 밟았다

| 함정 | 증상 | 대응 |
|---|---|---|
| **Whisper 가 구간을 통째로 빠뜨린다** | 53초를 한 번에 돌리니 결과가 6줄이고 **1.4~30초가 통째로 없었다.** 그 구간만 잘라 다시 돌리니 10줄이 멀쩡히 나왔다. **오류도 경고도 없다** | 전사 뒤 **커버리지 검사**. 소리 있는 구간(dBFS) 대비 자막이 덮은 시간 비율이 낮으면 격리하고 창을 잘라 재시도 |
| **원본에 욕설이 있다** | 스탠드업이라 f-word 가 전사에 그대로 잡힌다. 완성본에서는 그 대목이 자막에서 빠져 있었다 | 사전으로 걸러 그 줄을 빼거나 순화. 안 하면 수익화에 걸린다 |

첫 번째가 특히 위험하다. 100편 배치면 **몇 편은 자막이 반쯤 빈 채로 완성본 폴더에 들어간다.**

## 소재 판정은 화면이 아니라 전사로 한다

칩칩은 "화면에 사건이 있나" 라 눈이 필요하다(시트 상위에 1976년 잭슨파이브
아카이브가 올라온 적이 있고 어떤 수치로도 안 걸렸다). 그런데 영어 학습 클립의
적합성은 **전사에서 수치로 나온다.**

| 기준 | 재는 법 |
|---|---|
| 음질이 받아쓸 만한가 | Whisper `avg_logprob` |
| 표현 밀도 | 구동사·숙어가 몇 개 잡히나 |
| 발화 속도 | 낱말수 ÷ 초 |
| 욕설 | 사전 대조 |
| 문장이 끊겨 있나 | 세그먼트 길이 분포 |

★`avg_logprob` 이 실제로 갈린다 — 표본에서 **한국어 TTS 나레이션 구간이 `-0.71`,
원본 스탠드업 구간이 `-0.24`** 였다. 숫자만으로 "받아쓸 만한 음성이냐" 가 나뉜다.

→ 후보 300개를 받아 전부 전사하고 점수로 100개를 남기면 된다.

## 속도 실측

| | |
|---|---|
| `faster-whisper small` · 53초 전사 | **4초** (CPU, 모델 로딩 별도) |
| `faster-whisper medium` · 53초 전사 | 17초 (로딩 48초 별도) |

100편이면 small 로 10~15분이다. `faster_whisper 1.2.1` 이 이미 깔려 있다.

## 업로드 — 하루 6편이 상한이다

```
videos.insert  = 1,600 유닛 / 1편
기본 일일 할당 =   10,000 유닛   → 하루 6편
```

100편이면 **17일**이다. 증액은 구글 심사를 받아야 하고 잘 안 난다.
브라우저 자동화로 우회하는 길은 계정 정지 위험을 안으니 권하지 않는다.

**대신 `publishAt` 예약을 쓰면 100편을 한 번에 큐에 넣고 17일에 걸쳐 저절로
공개된다.** 손은 한 번만 댄다. 하루에 100편을 쏟으면 어차피 스팸으로 걸리니
이게 오히려 맞는 속도다.

## 100편 굽는 데 걸리는 시간 (추정)

| 칸 | 100편 |
|---|--:|
| 발굴 | 며칠 누적 (한 질의에 25~40건이라 하루로는 안 모인다) |
| 다운로드 | 1~2시간 |
| 전사 | **10~15분** |
| 번역 | 1시간 |
| TTS 200줄 | 1시간 |
| 렌더 | 2~3시간 |

저녁에 걸면 아침에 나와 있다. **다만 반드시 샘플 3편부터 굽고 화면을 대조한 뒤
100편으로 넘어간다** — 100편 다 굽고 제목 위치가 틀린 걸 발견하면 100편을 다 버린다.

## 남는 사람 자리

**검사에 걸린 것만** 보시면 된다. 100편이면 대략 15편쯤이다 —
자막 커버리지 미달 · 욕설 · 표현 3개 미만 · 길이 미달/초과.

★저 폴더의 100편이 **정말 검사 없이 나온 것인지, 걸린 걸 사람이 손본 건지는 모른다.**
어느 쪽이든 검사를 붙이는 쪽이 안전하다.

## 확인 못 한 것

- **글꼴** (제목 굵은 고딕 / 한국어 자막 / 영어 이탤릭) — 406×720 이라 자면 대조 불가
- 원본 프레임레이트 (표본은 24fps 인데 카카오 재인코딩 결과일 수 있다)
- 밴드 안 자막의 정확한 잉크중심 — 소재 위에 얹혀 있어 배경과 안 갈린다.
  원본을 받으면 어두운 컷에서 재야 한다 ([[builder-check-misreads-bright-and-dark-clips]])
- 오늘의 표현 표의 줄별 등장 시각 (t=50 에 9줄, t=53 에 12줄인 것만 안다)
